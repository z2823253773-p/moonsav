# MoonSav PRD 场景与问题复审

日期：2026-10-23；r0.1 → r0.2。状态：设计修订，不是产品实现/兼容性验收。用户要求进一步推敲用户场景及可能的问题；没有新增个人需求事实或试用反馈。

## 主要修订

| r0.1 的缺口 | 对实际用户的影响 | r0.2 的决定 | 验收落点 |
| --- | --- | --- | --- |
| 研究者/学生/开发者并列，缺乏优先级 | 容易做成泛用转换器，却无法回答 MoonBit 项目的价值 | 主用户明确为 MoonBit 集成开发者；CLI 服务检查/移交任务，稳定使用其他生态的用户不要求迁移 | U1、AC14 |
| 三个场景只是功能摘要 | 很多功能都实现了，用户仍可能无法走完任务 | 补齐起点、最短路径、成功结果、卡点；需求假设与事实分开 | U1–U3、AC14–17 |
| CSV 采用全局 `\N` 和反斜杠私有转义 | 通用工具看到被修改的路径/字符串，还需要专用反转义 | 撤销私有转义；数值系统缺失用空字段，字符串原样；完整语义另由同包权威 NDJSON 承载；单列全缺失须保留记录 | AC08 |
| metadata 虽然保留信息，却缺少消费路径 | 用户拿到 JSON 仍可能丢前导零、将 NA 文本变缺失，或忽略用户缺失 | 标准库跨语言读取示例、codebook、最小 MoonBit 消费者；日期及显示格式边界明确 | AC14、AC17 |
| 未明确字符串没有系统缺失 | 把空白字符串当 null，制造原文件不存在的语义 | Numeric 才允许 SystemMissing；String 始终带原值，按声明判断 UserMissing | AC07 |
| CSV“保留”缺乏层次区分 | 被误解为编码字节和 SAV 容器都能还原 | 完整 bundle 始终保留权威 NDJSON，默认另有 CSV 视图；仅文本不足以恢复不同字节对应的逐格语义；不承诺重写原容器 | AC08 |
| 严格解码被误当作可逆编码 | 不同源字节可能解为同一字符，丢失原字节，影响逐格缺失或标签关系 | 已由本机 Node 实验复核非单射；保留逐格原字节、缺失状态及字典键，并要求独立验证字符串匹配规则，不能据 codec 实验猜 SPSS 行为 | AC07/08/16 |
| 平台编码名被当作 SPSS 代码页的充分证明 | Node 和 Python 对部分 GB18030 字节结果不同，保留原字节也不能使错误文本正确 | M1 固定 profile/规范版本及映射证据，验证失败替换适配；不能笼统声称全部代码页变体兼容 | M1、AC06 |
| 仅有 manifest，没有配套文件校验入口 | 协作者可能把 A 的 CSV 配上 B 的字典而不自知 | 增加只读 check-bundle，验证版本、哈希、表头、类型与实际记录数 | AC16 |
| 输出目录改名被当作跨平台不覆盖事务 | 并发、目录已存在和中断行为可能与承诺不符 | 排他创建目录，INCOMPLETE 与最后提交；明确提交后报告失败的恢复边界 | AC11 |
| inspect 的成功范围容易被忽略 | 读取了字典，却宣传整个文件没损坏 | 分离声明行数/实际行数；dictionary_only 与 full 及 unknown 明确 | AC15 |
| 编码选定与编码正确未区分 | 选错但合法的代码页仍可能产生乱码 | 严格解码不称自动识别正确；覆盖和附加元数据有提示，保留声明来源 | AC06、AC15 |
| 数字标签元数据靠普通 JSON 数值 | 负零等精确表示可能丢失，甚至出现标签/数据不一致 | NumericAtom 明确 decimal+IEEE754 hex；冲突表示拒绝 | AC07、AC16 |
| 缺少自动化提示契约与恢复建议 | 脚本无法决定“可用但有提示”和“文件损坏”，用户不知道重试方式 | 稳定 JSON/exit/warning，fail-on-warning 及 suggested_action/output_state | AC15、AC17 |
| 大规模上限只有资源表 | 逻辑通过但小文件也很慢，或误称流式无上限 | 声明输入仍在内存；补代表性性能目标与实测要求，不宣称已达到 | AC18 |
| 原型只要求解析闭环 | 到产品化才发现 API 或导出根本接不上 | M1 同时做最小消费者与标准 CSV 反读，语料清单先冻结 | M1、AC01/14 |

## 范围控制

原有两种压缩、长字符串、标签、两类缺失和四种目标编码继续作为必需项。增加 checker、codebook 和消费示例，是为了交付原本承诺的“可用、保留语义的输出”，没有增加统计、GUI、批量处理、自动清洗或全格式支持。NDJSON 已在 r0.1 范围内，本次使它成为每个完整导出包的权威数据，代价是默认包更大，优于额外设计稀疏例外侧表或静默接受不可逆导出。扩展 11 的测量/显示信息纳入明确字段保留，避免被视为“数值类型已经表达了所有元数据”。

Node CLI 不要求使用者装 MoonBit；库消费者需要 MoonBit 工具链。各后端的编码适配边界保持明确，没有把 Node 能力冒充跨后端纯库能力。

## 新增来源和推论边界

- [IBM：字符串缺失](https://www.ibm.com/docs/en/spss-statistics/30.0.0?topic=data-missing-values-string-variable)、[GNU PSPP：缺失观察](https://www.gnu.org/software/pspp/manual/html_node/Missing-Observations.html)：字符串没有数值型系统缺失，但可以声明用户缺失。部分 GNU 页面实时读取超时，已用 IBM 官方及 GNU 官方索引内容交叉核查。
- [RFC 4180](https://www.rfc-editor.org/rfc/rfc4180)：本项目选用的 CSV 引述、逗号、记录分隔约定来源。RFC 是 Informational 文档，不能用它证明任意 CSV 工具会保留 SPSS 语义。
- [pandas read_csv](https://pandas.pydata.org/docs/reference/api/pandas.read_csv.html)：默认类型/NA/空行处理不能当作语义保证。项目采用显式类型/缺失恢复是产品选择，并不是声称已经验证某版本 pandas 的端到端表现。
- [Node v24 文件系统文档](https://nodejs.org/docs/latest-v24.x/api/fs.html)：存在性预检不应当作最终排他创建。具体目录提交协议是本项目设计，尚需并发、中断和跨平台验收证明。

r0.1 已保存在 [PRD-r0.1.txt](evidence/2026-10-23/PRD-r0.1.txt)，旧 `document-check.json` 与 `DESIGN_REVIEW.md` 只证明当时文档，不对 r0.2 生效。r0.2 的独立审查及新鲜文档检查另存证据；不得改写原记录使其看似审过新版。

## 独立审查与实际探测

独立 builder 审查确实指出了“CSV 文本无法普遍恢复源字节匹配语义”的阻断，而非直接给出无问题结论；修订为始终保留 canonical NDJSON、补齐字典原字节及待验证匹配规则后，复审返回 `nothing important left`。同时修正了各类使用者的运行前提和提交前清理顺序。审查属于设计自洽性检查，不证明 SPSS 的真实比较规则。

主代理也运行 Node 和 Python 严格 codec 探测，实际观察到解码非单射及实现间差异。数据和退出码见 [Node 结果](evidence/2026-10-23/decoder-noninjection-r0.2.json)、[Python 结果](evidence/2026-10-23/python-codec-comparison-r0.2.json)，均没有解析 SAV。编码 profile 作为 M1 必须解决的技术验证项，而不是让用户猜标准或无依据选一种结果。
