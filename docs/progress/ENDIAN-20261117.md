# 大小端阶段开发验证 · 2026-11-17

结论：匹配整数/IEEE754字节序的大小端SAV/ZSAV读取已完成本地开发验证；完整IBM26兼容目标及赛事验收仍未完成。没有推送、发布或替主办方作认可。

## 实现

MoonBit从layout_code识别字节序，传播到全部游标、数值缺失/标签、字节码生成值、11/16/21/22扩展和ZSAV64位目录。字符串/文本原字节不翻转。Dictionary/metadata/codebook/schema/Node类型保留byte_order，规范数值hex与源字节序无关。旧bundle省略该字段按历史小端默认；未知枚举拒绝。机器声明矛盾、未知layout、非法长度、截断、资源超限明确失败。

本阶段限匹配的IEEE754整数/浮点端序。IBM/VAX仍拒绝；标准100 bias反序时明确报UnsupportedFloat。不声称能自动识别任意非标准bias混合端序文件。原生/wasm-gc可直接读取普通/字节码大小端文件；ZSAV仍需调用方提供受限inflater，内置适配器是Node平台能力。

## 发现与保留的问题

1. 原negative-zero.sav还包含HIGHEST/LOWEST作为实际数据。ReadStat将两者标记为系统缺失，PSPP及MoonSav保留有限数值；大小端都出现同一分歧。已核对ReadStat的sav_tag_missing_double实现确实额外标记这两类值；并单独加入只含-0/+0/1.25的样例验证负零。原比较仍为supported_fail/classification=oracle_disagreement，未改为通过；IBM26实际行为待验证。
2. 独立PSPP对照脚本原用csv.DictReader，漏掉单列空字符串形成的空CSV记录，导致严格行数比较失败。改用csv.reader保留该真实记录，仍严格检查列数/行数；多次失败日志保留，修正后独立对照通过。
3. 初始开发转换器中Python的pos += integer()覆盖读取函数刚增加的偏移。先修正生成器并经ReadStat确认数据等价，再运行产品失败用例；不将生成器错误当作产品红测。
4. 无机器编码信息的文件仍须可信encoding声明或显式override。去除机器记录的用例先得到EncodingRequired，再用已知UTF8覆盖；没有为了端序测试增加编码猜测。
5. 原header-only伪大端损坏用例不再用“不支持大端”作为成功理由；损坏入口改测未知layout。真实大端、layout3、64位越界、声明矛盾另有明确测试。

依据：[GNU PSPP格式](https://pspp.benpfaff.org/manual/system-file.html)、[ReadStat缺失标记实现](https://github.com/WizardMac/ReadStat/blob/master/src/spss/readstat_sav_read.c)。仅对照格式行为，未复制解析器源码进产品。
