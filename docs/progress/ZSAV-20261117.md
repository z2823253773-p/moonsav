# ZSAV阶段开发验证 · 2026-11-17

结论：新增的小端IEEE754 ZSAV读取已经完成本地开发验证；不是IBM26完整兼容验收，不是赛事认可。旧c89ce1a归档及其子集验收不变，新源码尚未推送或发布。

## 实现与边界

MoonBit实现FL3与compression2一致性检查、64位头/尾/块目录校验、跨块字节码读取、原有变量/缺失/标签/长字符串重组和bundle语义。Node只使用内置inflateSync原语，设置解压上限并验证压缩输入全部消耗，不依赖外部SAV读取器。按块消费，未拼接整个解压文件。

新增Options.inflater及Limits.inflated_bytes；Node API为maxInflatedBytes，CLI为--max-inflated-bytes。累计上限256MiB，单块压缩/解压各16MiB，最多65536块；可下调累计上限。缺少inflater的可移植核心仍可inspect字典，完整读取则明确报UnsupportedCompression。Native/wasm-gc测试验证容器/失败契约，不能据此声称已经提供这两个后端的zlib运行适配器。

## 失败与分歧

- 初始npm test因沙箱禁止写入默认~/.npm缓存失败；仅改用进程级NPM_CONFIG_CACHE指向.dev/npm-cache，未改全局配置或权限。随后完整通过。
- TDD先保存FL3拒绝和缺失资源边界的失败；首次编译发现函数字段调用/不可变Bytes写入错误，后修正。原日志保留，不充当成功证据。
- ReadStat生成的合法零行ZSAV使用零压缩块。实现接受这种容器，零行恢复正确；不能机械套用文档概括中的“one or more”。
- 手工13字节块/非默认bias边界文件：PSPP与MoonSav恢复相同3×2数据，ReadStat报行数错误。此项明确列为oracle_disagreement，不计作ReadStat通过。尚未确定ReadStat分歧的具体原因，不据此认定ReadStat存在缺陷。
- 旧CI smoke曾将只有4字节的$FL3判作不支持压缩；格式新增后它应为Truncated/exit4。已先观测失败，再修正期望并增加已安装CLI读取真实ZSAV的检查。
- 编译仍有既有deprecated/reserved keyword等警告，构建成功不表示零警告。

## 复现与证据

固定环境：Node24.15.0/ICU78.2；moon0.1.20260713、moonc0.10.4+2cc641edf；Python3.12.13、pyreadstat1.3.3；PSPP2.0.1。生成器zlib1.2.12；实际产品用Node内置zlib。

```sh
npm run build
NPM_CONFIG_CACHE="$PWD/.dev/npm-cache" npm test
moon test --target js
moon test --target native
moon test --target wasm-gc
.dev/venv/bin/python tools/rejections.py evidence/zsav-fresh-rejections
.dev/venv/bin/python tools/verify_zsav.py --output evidence/zsav-fresh-oracles
NPM_CONFIG_CACHE="$PWD/.dev/npm-cache" node tools/ci_smoke.mjs
```

oracle输出目录必须不存在。生成器tools/generate_zsav.py固定合成文件头日期时间，其余输出来自独立生产者。fixtures/synthetic/zsav-provenance.json记录每个文件的实际SHA256和版本。

机器汇总：[evidence/zsav-20261117/summary.json](../../evidence/zsav-20261117/summary.json)。本地完整命令/退出状态/失败日志在同目录分组run.json中；原始开发工作区的HEAD为b377437，dirty=true，新源码以build.source_tree_sha256定位，不能冒充干净发布版本。完整历史日志仅本地保留，仓库中保留紧凑汇总、最终oracle结果及固定样例。
