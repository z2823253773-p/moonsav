## 1. 拟明确的版本端点

建议以 **IBM SPSS Statistics 26.0 的 SAVE /VERSION=3 现代系统文件**作为兼容基准，完整读取该基准版本合法产生的数据与字典，涵盖普通 SAV 与 ZLIB 压缩系统文件 ZSAV。26.0 是指定参考生产者版本，不据此声称存在一种名为“SAV26”的独立二进制规范。

IBM 的 SAVE /VERSION=3 是默认现代保存格式选项；/VERSION=2 用于旧版本兼容。它与文件头的 `$FL2`/`$FL3` 不同：后者区分传统数据存储与 ZLIB 压缩，不能把 `$FL3` 自动解释成 SAVE VERSION=3。

参考依据：[IBM26 命令参考](https://public.dhe.ibm.com/software/analytics/spss/documentation/statistics/26.0/en/client/Manuals/IBM_SPSS_Statistics_Command_Syntax_Reference.pdf)、[IBM VERSION说明](https://www.ibm.com/docs/en/spss-statistics/30.0.0?topic=save-version-subcommand-command)、[IBM26用户指南](https://www.ibm.com/docs/SSLVMB_26.0.0/pdf/en/IBM_SPSS_Statistics_Core_System_User_Guide.pdf)、[GNU系统文件说明](https://www.gnu.org/software/pspp/pspp-dev/html_node/System-File-Format.html)。30.0页面用于交叉核对版本选项，端点仍以26.0手册为准。

## 2. “完整”必须落实到以下维度

| 维度 | 新端点承诺 | 当前实现差距 |
| --- | --- | --- |

| 编码 | 目标版本合法输出的Unicode及本地代码页；严格按声明解码并保留来源，不以四项白名单为终点 | 四项有边界profile不能证明完整编码覆盖 |
| 变量与字符串 | 数值、短/长字符串、延续/分段、长名、标签、编码后的逻辑字节宽度 | 原范围大部已有，须在新增存储组合上交叉复验 |
| 缺失与格式 | 系统缺失、用户离散/范围/范围加单值、字符串缺失、原始print/write日期和数值格式 | 原范围已有；新增压缩/端序/编码下需重证 |
| 版本字典 | 文件和变量说明、权重引用、测量/显示、变量集合、多重响应集合、文件/变量属性等目标版本合法字典信息 | 若干记录目前只保留raw载荷；不能因此声称相应语义完整 |
| 合法保存选项 | 逐项审计26.0 SAVE语法；密码保护等合法形式不得在完整承诺中默默排除 | 当前无密码接口或解密能力，需规划并验收 |
| 安全与失败 | 损坏长度、截断、错误密码、未知版本和超限明确失败；不丢列、不替换解码、不隐式抽样 | 原范围契约可复用，新增入口必须覆盖 |

完整读取指库能取得并表达相应数据与字典语义，不承诺执行SPSS统计过程或写回文件。POR、SAS、Stata和SAVE/VERSION=2是其它格式/版本，另行描述；不能用它们冲淡本端点。不能将目标版本内合法但尚未实现的扩展列为“范围外”来宣告完成。资源上限与格式能力分开：超过公开预算返回ResourceLimit，不截断后成功，也不伪称所有大小已测。

代码中的opaque/raw保留对可恢复性有用，但若尚不能表达已知重要字典语义，应标记未完成。密码功能需提供明确接口，密码不进入日志、manifest或公开样例配置；仅采用合成密码测试，不能上传私人原件。

## 3. 同一调查的合法存储形式

共同调查有3行6列：subject_code、group、score、answer、long_note、visit_date。编号依次为字符串0012、NA、反斜杠N；score为88、声明用户缺失99、系统缺失；answer为Y、N、声明用户缺失X。带中文变量/值标签、超过255字节的中文备注和DATE11日期格式。

| 形式 | 编码 | 预期逻辑读取结果 | 当前证明 |
| --- | --- | --- | --- |
| 未压缩SAV | UTF8 | 3行6列，全部值、标签、缺失和日期格式按共同模型恢复 | ReadStat生成/回读一致；MoonSav exit0 |
| 传统字节码压缩SAV | UTF8 | 同上 | 同上 |
| ZLIB压缩ZSAV | UTF8 | 同上 | 历史探针exit5；当前阶段读取/导出成功，常用调查ReadStat与PSPP对照一致 |
| 未压缩/传统压缩SAV | 可表达此数据的本地CP936 | 同上，合法编码所致的原始字节/宽度差异另记录 | 待生成与验证，不计为已通过 |
| 合法大端及密码保护变体 | 按26.0规范与密码条件 | 解码/解密后同一模型，错误密码明确失败 | 待实现与独立验证 |

旧冻结版本前三项的真实命令、SHA、工具版本、当前HEAD和退出状态见 `docs/submission/revision-20261117/same-survey-observation.json`；生成脚本同目录。生产者是pyreadstat/ReadStat，不是IBM SPSS26，不能把product字段改成IBM来冒充原版生成样例。

共同预期计数（顺序present/user/system）：score为1/1/1，answer为2/1/0，其余列为3/0/0。日期保持原double及DATE11，标签不替换原值，ID不改数值，字面NA不猜缺失，长字符串在重组后解码。数据来源为自建合成记录，无私人原始数据。

比较逻辑数据与字典含义，不要求不同编码/压缩文件有相同文件哈希、偏移、压缩标识或源字节；这些存储属性必须如实分别保留。跨代码页转换只测试双方都能无损表达的共同字符；不能把中文转为问号后声称同一调查。CP1252不能无损表达本例中文，应使用另一个西欧字符调查作该编码的完整语料，不强行生成所谓合法等价文件。
