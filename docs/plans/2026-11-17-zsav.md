# ZSAV milestone implementation plan

> Execute inline using superpowers:executing-plans. The existing PLAN.md authorizes direct execution; “下一步” continues the documented compatibility expansion. No public push, merge or release is included.

**Goal:** Read little-endian IEEE754 FL3/ZLIB system files through the MoonBit library and Node CLI, with cross-storage semantic comparison and bounded, strict decompression. This milestone alone does not satisfy the IBM26 full-compatibility endpoint.

**Architecture:** MoonBit validates the ZSAV header/trailer/block directory and feeds the inflated byte stream into its existing bytecode/row reader. A caller-supplied inflater is a bounded RFC1950 primitive; Node implements it with built-in zlib and verifies complete compressed-input consumption. Inflation proceeds one block at a time, including 8-byte reads crossing block boundaries. `inspect` remains dictionary-only and needs no inflater.

**Spec:** ../COMPATIBILITY_TARGET.md; GNU PSPP Data Record documentation, https://pspp.benpfaff.org/manual/system-file.html#Data-Record .

## Constraints and decisions

- Existing product/source/acceptance archives remain historical. Original PRD excludes ZSAV; this plan is its explicitly authorized compatibility expansion, not a retrospective acceptance rewrite.
- Work in the user-designated standalone moonsav checkout, as the existing PLAN.md execution ledger specifies; do not change the retained integration worktree or stage untracked personal proposal/acceptance files.
- Add `Options.inflater : ((Bytes, Int) -> Bytes raise SavError)?`; the integer is the expected and maximum decoded block length. A missing adapter returns UnsupportedCompression on a data scan, never fake rows.
- Add `Limits.inflated_bytes`, compiled maximum/default 268435456, and Node `maxInflatedBytes` / CLI `--max-inflated-bytes`. This is a separate total inflation budget; input-file and row budgets retain their meaning.
- Source compression remains 2 in dictionary/bundles/types. No external SAV parser or new runtime npm dependency.
- Unknown compression, contradictory magic, invalid lengths/offsets/overlap, corrupt/trailing zlib bytes and wrong output lengths fail explicitly. No unconstrained concatenation of all inflated data.
- Original IBM26, big endian, further encodings, complete dictionary semantics and password support remain later milestones, never counted as passed here.

## Review focus

1. Valid bytecode controls/literals crossing compressed-block boundaries must reconstruct exactly.
2. Forged 64-bit offsets/counts must fail before allocation or inflater calls.
3. Small compressed streams expanding past declared sizes or the total budget must not allocate unbounded output.
4. Truncated/checksum-damaged/trailing/concatenated zlib data must not be silently accepted; failed exports must not commit.
5. Installed package and portable core without an adapter must report honest, different capabilities.
